# Build notes, Week 1 foundation

Date: 26 Nov 2026. Author: iOS Engineering Lead.

## What this build is

Week 1 foundation only, per the roadmap: Xcode project, SwiftData model,
tab navigation shell, design tokens, seed data, journal create and edit
flow. This is NOT a TestFlight build. No TestFlight build is promised

## What was written

- `DanceProgressionJournal.xcodeproj`, generated by
  `tools/generate_xcodeproj.py`. App target DanceProgressionJournal,
  unit test target DanceProgressionJournalTests. iOS 17.0 deployment
  target, iPhone only, Swift 6 language mode, bundle ID
  `com.codeair.danceprogressionjournal`, marketing version 1.0.0 build 1.
  Release builds treat warnings as errors.
- `DanceProgressionJournal/Models/Models.swift`: all 10 SwiftData
  entities from roadmap section 7, with the relationships listed there.
  Video bytes live in Application Support in a Videos folder, one file
  per asset, UUID plus extension filename. SwiftData stores the relative
  path only.
- `DanceProgressionJournal/Persistence/PersistenceController.swift`:
  one ModelContainer at launch, versioned schema 1.0.0 from day one,
  migration plan with no stages yet. A corrupt store falls back to an
  empty in memory store so launch never crashes.
- `DanceProgressionJournal/DesignSystem/DesignTokens.swift`: full light
  and dark palette, type scale, 8 point spacing grid, corner radii,
  motion, icon sizes, exactly from `docs/design/01_design_tokens.md`.
  Brand accent is provisional pending May's choice by 2 Dec 2026.
- `DanceProgressionJournal/DesignSystem/Components.swift`: primary,
  secondary, destructive and text buttons, cards, list rows, filter
  chips, category tags, search field, empty state, error banner,
  countdown display, checklist rows, confidence selector, per
  `docs/design/02_components.md` and `03_accessibility.md`.
- `DanceProgressionJournal/Repositories/`: repository protocols plus
  SwiftData implementations. This is the seam for Firebase sync in
  Phase 2. Views and view models never touch a ModelContext.
- `DanceProgressionJournal/Services/`: VideoFileService (Application
  Support Videos folder, thumbnails) and CategorisationService (local
  rules only, protocol seam for a future on device model).
- `DanceProgressionJournal/Navigation/Routes.swift`: typed routes per
  tab, no string based routes. Four tabs: Journal, Library, Progress,
  Settings.
- `DanceProgressionJournal/Views/`: Welcome and Setup, Home Dashboard,
  Journal List, Journal Entry Detail, Create and Edit Journal Entry,
  Competition Detail with countdown and checklist, Library with
  Videos, Figures and Drills segments, Video, Figure and Drill detail,
  Progress with Insights and Practice History, Settings and Local
  Profile.
- `DanceProgressionJournal/Seed/SeedData.swift`: the sample data set
  from `docs/design/04_sample_data.md`, exactly as written. Dancer May,
  the 5 International Latin dances, 3 journal entries, 3 drills,
  2 videos (metadata rows only, no video bytes), 6 figures, 8 practice
  sessions, sample NDCA competition as a relative countdown only.
  Alemana and Fan are labelled pending the client NDCA list in the UI.
- `DanceProgressionJournalTests/`: 16 unit tests (swift-testing):
  seed counts and totals, entry edit keeps links, entry delete scope,
  categorisation rules, video file save and delete round trip,
  repository filters and mark practiced.

## How to build on a Mac

1. Pull latest main.
2. Open `DanceProgressionJournal.xcodeproj` in Xcode 26.1.
3. If Xcode reports project file issues, re run
   `python3 tools/generate_xcodeproj.py` from the repo root and reopen.
4. Select the DanceProgressionJournal scheme, pick an iPhone simulator
   (iPhone 15, iOS 26 is the reference device), press Build.
5. Fix any compile errors. Likely first suspects, because no compiler
   has seen this code yet: SwiftData relationship declarations, the
   `@Bindable` locals in form views, `ShareLink` initializer arguments,
   `#Predicate` captures in `@Query` initializers.
6. Run the unit tests with Product, Test.
7. Run the app. First launch shows Welcome and Setup. Continue or Skip
   to reach Home Dashboard with the seeded sample data.
8. Before any TestFlight step: set the development team for signing in
   the app target, confirm bundle ID
   `com.codeair.danceprogressionjournal` is free in App Store Connect,
   and confirm May's Apple Developer enrolment (needed by 30 Nov 2026).

## Two token files, read this

The design team committed `DesignSystem/DesignTokens.swift` at the repo
root. The app target uses
`DanceProgressionJournal/DesignSystem/DesignTokens.swift`. All 18 colour
hex values match exactly between the two files. The files differ in API
shape: the root file uses fixed font sizes, the app file uses relative
text styles so Dynamic Type works, per `docs/design/03_accessibility.md`.
The root file is the design team's work and was not touched. Reconcile
the two at the Week 1 review: either the root file becomes the target
member, or the app file replaces it. Do not let them drift.

Reconciled 26 Nov 2026: the app target file replaced the root copy, so
both files are byte identical. The app file is canonical. No view or
component uses the root file's `ColorToken`, `FontToken`, `Layout` or
`cardPadding` members, so nothing was lost. If a token changes, change
it in the app file and copy it to the root file in the same commit.

## CI, first runs 26 Nov 2026

GitHub Actions workflow `.github/workflows/ios.yml` runs on
macos-latest with the newest Xcode, `xcodebuild test` on the shared
scheme `DanceProgressionJournal`, iPhone 17 simulator,
`CODE_SIGNING_ALLOWED=NO`. Fixes applied in order:

1. Runner has no iPhone 16 simulator, destination changed to iPhone 17.
2. The AppIcon set was empty, a placeholder 1024 icon in the
   provisional accent colour was added, then completed to the full
   classic set (8 iPhone sizes plus 1024 marketing icon).
3. Swift 6 fixes: `VideoFileService` drops `Sendable` (FileManager is
   not Sendable); `RelativeDateFormatter.shared` is `@MainActor`
   (DateFormatter is not Sendable); `fetch(byCategory:)` and
   `fetch(byLevel:)` filter enums in memory because enum comparison is
   not supported inside `#Predicate` on this SDK.
4. Project file path bug, the real blocker: `tools/generate_xcodeproj.py`
   wrote repo relative paths into every `PBXFileReference`, but a
   file reference with sourceTree `<group>` resolves relative to its
   containing group, and every group already carries its directory in
   its own path. Every file resolved to a doubled path that does not
   exist, so actool failed with "No such file or directory" and no
   AppIcon set was found. Fixed in the generator (file references now
   carry the bare file name) and the project file was regenerated.
   All 26 file references now resolve to real files on disk.
   The `INFOPLIST_FILE` build setting stays project relative
   (`DanceProgressionJournal/Info.plist`) and is correct as is.

Test count note: the test target holds 18 tests, not 16 (ModelTests
10, CategorisationTests 4, VideoFileServiceTests 2, RepositoryTests 2).
